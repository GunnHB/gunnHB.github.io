## 라우팅을 알아야 하는 이유
> PC A(192.168.10.30/24)에서 PC B(192.10.20.10/24)로 데이터를 보내고 싶다.

같은 네트워크라면 스위치같은 장비를 통해 직접 전달이 가능하겠지만 위 상황은 다른 네트워크이므로 직접 전달이 불가능하다. 이 문제를 해결하기 위한 것이 **라우팅**<sup>routing</sup>이다.

## 라우팅, 라우터, 라우팅 테이블
라우팅 과정을 이해하기 전 우선 필요한 개념을 정리하면 다음과 같다.

- **라우팅**<sup>routing</sup>: 목적지 IP 주소를 기준으로 패킷을 어느 경로로 보낼지 결정하는 과정
- **라우터**<sup>router</sup>: 서로 다른 네트워크를 연결하고 목적지 IP에 따라 패킷을 적절한 네트워크로 전달하는 장비
- **라우팅 테이블**<sup>routing table</sup>: 목적지 네트워크별로 패킷을 어디로 보낼지에 대한 경로 정보의 집합

## 라우팅 테이블을 통해 라우팅 이해하기
리눅스 환경에서 라우팅 테이블을 확인하기 위해서는 터미널에 `ip route`을 입력하면 된다. 명령의 결과 예시는 다음과 같다.

```bash
192.168.10.0/24 dev eth0
10.20.0.0/16 via 192.168.10.254 dev eth0
default via 192.168.10.1 dev eth0
192.168.10.0/24 dev eth0 src 192.168.10.10
```

각 한 줄이 라우트<sup>route</sup>다. 즉, 패킷을 보낼 경로를 의미하는 것이다.

이는 다음과 같이 해석할 수 있다.

> 현재 PC의 IP 주소는 `192.168.10.30/24`로 가정한다.
{: .prompt-info}

### 192.168.10.0/24 dev eth0

> 목적지가 `192.168.10.0/24` 네트워크에 속한다면 eth0으로 보내라

만약 목적지 IP가 `192.168.10.50/24`이라면 `192.168.10.0/24`에 포함되기 때문에 `eth0`으로 패킷을 전달하라는 의미이다. 이는 두 호스트가 같은 네트워크에 포함되기 때문에 라우터를 거치지 않고 **직접 전달**된다.

> eth0은 패킷이 나가는 출구로 이해하면 된다. 정확히는 Linux에서 사용하는 네트워크 인터페이스(Network Interface)의 이름이며, 일반적으로 물리적인 NIC와 연결되어 네트워크로 데이터를 송수신하는 데 사용된다.
{: .prompt-info}

### 10.20.0.0/16 via 192.168.10.254 dev eth0

> 목적지가 `10.20.0.0./16` 네트워크에 속한다면 `192.168.10.254`를 Next Hop으로 하여 eth0으로 보내라

만약 목적지 IP가 `10.20.30.40/16`이라면 `10.20.0.0./16`에 속하게 되여 `192.168.10.254`에 패킷을 전달한다. 두 네트워크는 서로 다른 네트워크에 속하므로 다음 라우터(`192.168.10.254`)에게 넘기게 된다.


### default via 192.168.10.1 dev eth0

> 어느 네트워크에도 속하지 않는 목적지 IP라면 `192.168.10.1`를 Next Hop으로 하여 eth0으로 보내라

목적지 IP가 어느 네트워크에도 속하지 않는다면 `192.168.10.1`에 패킷을 전달한다. 예를 들어 `8.8.8.8`이라는 목적지는 라우팅 테이블에 의하면 어느 네트워크에도 속하지 않는 것이다.

> 여기서 `192.168.10.1`는 일반적으로 **Default Gateway**를 의미한다.
{: .prompt-info}

### 192.168.10.0/24 dev eth0 src 192.168.10.10

> 목적지가 `192.168.10.0/24` 네트워크에 속한다면 출발지 IP를 `192.168.10.10`로 설정하여 eth0으로 보내라

이는 패킷을 보내기 전에 출발지의 IP를 초기화한다. 상황에 따라 IP를 여러 개 가질 수 있기 때문에 어떤 주소를 출발지로 우선 사용할지 정하기 위함이다.

### Longest Prefix Match
다음과 같이 라우팅 테이블이 구성됐다고 해보자.

```bash
10.0.0.0/8
10.20.0.0/16
10.20.30.0/24
0.0.0.0/0
```

이때 목적지가 `10.20.30.50`라면 **각 라우트에 모두 일치**하게 된다. 이럴 땐 가장 구체적인 경로를 선택하게 된다. 즉, `10.20.30.0/24`가 되는 것이다. 이를 **Longest Prefix Match**라고 한다.
